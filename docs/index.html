Go 的 goroutine 栈增长，为什么会吃掉 Uber 近 4% CPU？
Uber 大规模 Go 服务集群发现，goroutine 栈增长竟然消耗了约 3.9% 的 CPU。问题出在 Go Runtime 现有的自适应栈大小机制无法及时捕获短生命周期 goroutine 的栈需求。Uber 工程师 Krishna Swaroop 将生产实践带回 Go 社区，通过栈缓存、内存预算和 token 机>制，探索降低 Stack Growth 成本的新方案。这场优化也让我们重新认识了 Go Runtime 中一个容易被忽略的性能瓶颈。
