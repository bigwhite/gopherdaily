再见，Go map 的渐进式扩容！Go 1.28 将迎来 maps.Grow
Go 语言的 map 虽使用便捷，但面对已存在的 map 进行大批量追加写入时，无法主动预留空间、易引发多轮渐进式扩容与内存抖 动的痛点长期存在。Go 团队近期正式接受并完成了 Proposal #81698：将在 Go 1.28 的标准库中引入 maps.Grow，并同步为 maps.Copy 赋予自 动预扩容能力。实测大 map 批量复制耗时最多锐减约 57%，内存分配减少约 50%。本文深度解析新 API 的设计细节、性能基准及背后的工程哲学。

为什么一个 JSON 库，Go 团队花了六年才重写完？
Go 1.27 正式引入稳定版 `encoding/json/v2`，标志着一项持续近六年的标准库重构工作终于落地。这项工作源于旧版 `encoding/json` 长期存在的设计缺陷：严格性不足、API 扩展困难、流式处理能力有限，以及性能上的结构性瓶颈。由于 Go 1 兼容性承诺，Go 团队>无法直接修改旧 API 的既有行为，只能另起炉灶，重新设计 JSON 处理架构。从 2020 年的原型探索，到社区公开讨论、正式 Proposal、Go 1.25 实验，再到 Go 1.27 正式稳定，JSON v2 不仅重构了 JSON 处理机制，还通过统一底层实现，让新旧 API 能够长期共存。这六年，Go 团队>交付的不只是一个新 JSON 库，更是一堂关于大型基础设施如何演进的工程课。
